# Совместная работа над Родословной

Эта инструкция поможет Наталье получить существующий проект, запустить его в Codex и предложить изменения владельцу через PR, запрос на включение изменений. Для установки и команд нужны Windows, PowerShell, Git и Node.js 24. Порядок первого запуска приведен в [корневой инструкции](../README.md#запустите-приложение).

Для клонирования публичного репозитория и локальной работы учетная запись GitHub не нужна. Для отправки своих веток и создания PR зарегистрируйтесь в GitHub. Затем передайте владельцу имя учетной записи: после этого он сможет пригласить вас в основной репозиторий. Создать собственную копию на GitHub, fork, можно только после регистрации.

Ветка `main` защищена: для обычного участника требуются PR, одобрение назначенного владельца кода и успешная проверка `Проверки Windows и Edge`. Новые коммиты сбрасывают прежнее одобрение; обсуждения нужно закрыть до включения изменений. Владелец репозитория сохраняет административный обход правил, но Codex не применяет его автоматически: отправка и объединение требуют прямой команды владельца.

Клонируйте [существующий репозиторий](https://github.com/TomashPetersen/rodoslovnaya). Копирование шаблона нового проекта здесь не требуется. В Codex откройте корневую папку клона, где находятся `AGENTS.md`, `INDEX.md` и каталог `app/`. Если папка не добавилась автоматически, один раз добавьте ее как локальный проект; см. [документацию локальных проектов Codex](https://learn.chatgpt.com/docs/projects#use-local-projects-for-folders-and-codebases).

## Дайте Codex задачу первого запуска

Вставьте в свой Codex следующий запрос:

```text
Клонируй существующий проект
https://github.com/TomashPetersen/rodoslovnaya.git
в отдельную папку rodoslovnaya.
Если такая папка уже существует, сначала проверь ее содержимое и Git;
не перезаписывай существующие файлы и не создавай второй продукт из шаблона.

Прочитай AGENTS.md, INDEX.md, KNOWLEDGE-POLICY.md,
knowledge/CURRENT-STATE.md и knowledge/collaboration.md.
Работай с файлами этого репозитория; личная общая база владельца не нужна.
Отвечай по-русски, без длинного тире. Сохраняй точные команды, пути и имена.

Проверь Node.js 24, выполни npm.cmd ci из app/ и запусти npm.cmd run dev.
Покажи локальный адрес и результат проверки стартового экрана.
Для испытаний используй вымышленные данные и отдельный профиль браузера.
Не очищай существующее хранилище семьи.

Пока не меняй продукт и не выполняй commit, push, создание PR или публикацию.
Следующую задачу я дам отдельно.
```

Дополнительная справка: [локальная среда Codex](https://learn.chatgpt.com/docs/environments/local-environment).

Убедитесь, что открыта корневая папка проекта, а локальный адрес показывает «Родословную». Вы получили код, документацию и вымышленные наборы испытаний. История чатов другого участника, его личная общая база, внешние навыки, настройки и семейные сведения с Git не переносятся. Каталог `node_modules` создается при установке зависимостей.

## Начните задачу после приглашения в репозиторий

Рекомендуемый путь - принять приглашение владельца и получить доступ на запись в основной репозиторий. Каждую задачу выполняйте в отдельной ветке; для Натальи используйте `codex/natalya/TASK_SLUG`. Отправляйте ветку задачи, не меняйте `main` напрямую.

1. Из корня проекта проверьте адреса удаленных репозиториев:

   ```powershell
   git remote -v
   ```

   Этот порядок применяется, только если адреса получения и отправки `origin` ведут в основной репозиторий `TomashPetersen/rodoslovnaya`. Приглашение не меняет `origin` уже существующего клона. Если вы клонировали свою копию на GitHub, продолжайте [работу через собственную копию](#работайте-через-собственную-копию) с получением изменений из основного репозитория `upstream`. Перенастройка адресов - отдельное осознанное решение; Codex не должен менять их автоматически после приглашения.

2. Проверьте незавершенную работу:

   ```powershell
   git status --short
   ```

   Если есть изменения, сначала разберитесь, кому они принадлежат и как их сохранить. Не переключайте ветку поверх чужой работы.

3. При чистом рабочем дереве перейдите на основную ветку:

   ```powershell
   git switch main
   ```

4. Получите принятую версию проекта:

   ```powershell
   git pull --ff-only
   ```

   Если команда завершилась ошибкой, разберите причину до продолжения. Не заменяйте ее принудительным обновлением.

5. Создайте ветку задачи:

   ```powershell
   git switch -c codex/natalya/TASK_SLUG
   ```

   Замените `TASK_SLUG` коротким названием задачи латиницей с дефисами. Ветка должна иметь отдельное имя для каждой задачи.

6. Дайте Codex конкретное описание ожидаемого результата. Попросите прочитать [инструкции агента](../AGENTS.md) и выбрать [маршрут задачи](INDEX.md#маршруты-задач). Для изменения продукта используйте [единый план](../plans/2026-11-15-rodoslovnaya-mvp-pwa.md), а для обновления документов - [политику знаний](../KNOWLEDGE-POLICY.md).

## Работайте через собственную копию

Без доступа на запись используйте fork, собственную копию репозитория на GitHub. Этот путь подходит и после приглашения, если вы продолжаете работать с прежним клоном своей копии. Обычное клонирование создает локальные файлы; fork создает отдельный репозиторий в вашей учетной записи. Из своей копии можно предложить изменения основному проекту.

1. Если собственной копии еще нет, на странице основного репозитория создайте ее с помощью **Fork**.
2. Если своя копия еще не клонирована, клонируйте ее. В запросе первого запуска замените адрес основного репозитория адресом своей копии. Если основной проект уже клонирован, укажите другую свободную папку, например `rodoslovnaya-natalya`.
3. Попросите Codex проверить адреса Git: `origin` должен вести в вашу копию, а `upstream` - в `https://github.com/TomashPetersen/rodoslovnaya.git`. Затем получить актуальную `main` из `upstream` и создать от нее ветку `codex/natalya/TASK_SLUG`. Замените `TASK_SLUG` коротким названием задачи латиницей с дефисами. Используйте чистое рабочее дерево и сохраняйте чужие изменения.
4. Выполните задачу и проверки из следующего раздела. После прямой команды на отправку публикуйте ветку только в свой `origin`. Откройте PR из этой ветки в `main` репозитория `TomashPetersen/rodoslovnaya`.

## Проверьте результат и предложите изменения

1. Попросите Codex выполнить проверки из [инструкции приложения](../app/README.md#проверки-и-границы-поддержки) и [проверки базы знаний](../scripts/README.md). Браузерным испытаниям нужны Microsoft Edge и предварительная сборка приложения. Запишите команды, результаты, ошибки и пропуски; проверяйте только вымышленные данные.
2. Просмотрите измененные файлы и поведение приложения. Для документов отдельно выполните языковую вычитку. Проверьте, что в изменения не попали семейные данные, секреты или личные настройки.
3. После проверки дайте Codex прямую команду создать коммит из перечисленных файлов, отправить только ветку задачи и открыть PR в `main` основного репозитория. При выбранном пути с `origin` основного репозитория ветка находится в общем репозитории; при работе через fork - в вашей копии, в том числе после приглашения. Перед отправкой обязателен полный набор проверок проекта; `git add .` и `git add -A` не использовать.
4. В описании PR укажите задачу, поведение после изменения, результаты проверок и оставшиеся ограничения. Передайте ссылку владельцу проекта.
5. Дождитесь проверки со стороны владельца. Если нужны исправления, внесите их в ту же ветку и повторите затронутые проверки. Слияние, то есть включение PR в `main`, выполняется только по прямой команде владельца. Публикация приложения требует отдельной команды.

Работа готова к передаче, когда PR содержит проверенные изменения и результаты испытаний. Следующую задачу начинайте от актуальной `main` основного репозитория в другой ветке.

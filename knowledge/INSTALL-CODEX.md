# Полная установка «Родословной»: инструкция агенту Codex

Ты помогаешь Наталье установить существующий проект на ее компьютер и подготовить его к разработке. Прочитай эту инструкцию целиком, затем выполни установку, проверки и первый запуск. Не ограничивайся пересказом шагов. В конце сообщи путь к проекту, адрес приложения и фактические результаты.

Репозиторий: [TomashPetersen/rodoslovnaya](https://github.com/TomashPetersen/rodoslovnaya). Основная ветка: `main`. Для получения исходников и локальной работы учетная запись GitHub не нужна. Для отправки веток в основной репозиторий понадобится регистрация и приглашение владельца.

Эта инструкция рассчитана на уже открытый Codex с доступом к локальным файлам, терминалу и интернету. Если самого приложения нет, Наталья устанавливает его и входит в свою учетную запись по [официальной инструкции OpenAI](https://learn.chatgpt.com/docs/quickstart). Учетная запись приложения и учетная запись GitHub - разные вещи.

## 1. Проверь компьютер и сохрани существующую работу

Определи операционную систему, архитектуру процессора, доступные команды и свободное место на диске проекта и временных файлов. Подтвержденная среда проекта - Windows с PowerShell, Node.js 24 и Microsoft Edge. На другой ОС используй соответствующие официальные установщики и команды `npm` вместо `npm.cmd`; не объявляй браузерную совместимость подтвержденной и не меняй конфигурацию ради успешной проверки.

Выбери отдельную локальную папку для проекта, например `Projects/rodoslovnaya` внутри домашнего каталога Натальи. Вычисли ее абсолютный путь для этого компьютера. Не используй пути с компьютера владельца, сетевые папки или автоматически синхронизируемые каталоги для первой установки.

Если папка уже существует, сначала проверь ее содержимое, `git status --short`, ветку и `git remote -v`. Не перезаписывай файлы, не выполняй `reset --hard`, очистку или удаление. Для чужой папки выбери другое свободное имя. Для существующего клона сохрани незавершенную работу; обновляй чистую `main` только через `git pull --ff-only` после проверки адреса репозитория.

В Windows проверь доступность инструментов:

```powershell
Get-Command git, node, npm.cmd -ErrorAction SilentlyContinue
git --version
node --version
npm.cmd --version
```

Отсутствующая команда означает, что нужен следующий шаг. Версия Node.js должна начинаться с `v24.`. Не принимай наличие другой основной версии за выполненное условие.

## 2. Установи недостающие инструменты

Устанавливай только недостающее из официальных источников. Сохраняй ограничения и запросы подтверждения своей среды. Если требуется системное подтверждение или вход, передай Наталье конкретное действие, затем продолжи установку после него. Не меняй защиту Windows и системную политику PowerShell.

1. Установи Git по [инструкции Git для Windows](https://git-scm.com/install/windows). Если доступен WinGet, средство установки программ Windows, официальный сайт приводит команду:

   ```powershell
   winget install --id Git.Git --exact --source winget
   ```

   При отсутствии WinGet используй установщик с указанного сайта. Выбери архитектуру этого компьютера.

2. Установи Node.js именно ветки 24.x вместе с npm, средством установки зависимостей. На [официальной странице Node.js](https://nodejs.org/en/download/) выбери версию 24.x, Windows и подходящую архитектуру; установи пакет `.msi`. Если нужная ветка не предложена, используй [официальный каталог выпусков 24.x](https://nodejs.org/dist/latest-v24.x/). Не выбирай другую основную версию только потому, что она предложена по умолчанию.

   Если другая версия Node.js нужна существующим проектам, сохрани ее. Используй уже установленное средство переключения версий либо официальный архив Node.js 24 формата ZIP в отдельной папке инструментов и задай путь к нему только для процессов этого проекта. Не устанавливай дополнительные средства сборки или Python без конкретной ошибки, которая подтверждает необходимость.

3. Проверь наличие Microsoft Edge. Если его нет, установи браузер с [официального сайта Microsoft](https://www.microsoft.com/edge/download). Браузерные испытания используют установленный Edge через `channel: 'msedge'`. Команда установки Chromium из Playwright, средства браузерных испытаний, не заменяет Edge.

После установки открой новый терминал или обнови окружение процессов Codex. Повтори команды проверки из первого раздела в том терминале, где будешь устанавливать зависимости. Если приложение продолжает видеть старое окружение, сохрани работу и перезапусти его. Запиши фактические версии и найденные пути.

Для приложения не нужны отдельный сервер базы данных, Docker, API-ключи или файл `.env`. Семейная база IndexedDB создается в браузере самим приложением. Не устанавливай программы исследования, не запрашивай личную базу знаний владельца и не копируй его `node_modules`.

## 3. Получи полный проект

Если в первом разделе уже выбран существующий проверенный клон с чистой `main`, пропусти клонирование и перейди в его корень. Для новой папки из выбранного родительского каталога выполни:

```powershell
git clone --branch main https://github.com/TomashPetersen/rodoslovnaya.git rodoslovnaya
cd rodoslovnaya
```

Используй выбранное свободное имя вместо `rodoslovnaya`, если исходное занято. Это клонирование существующего продукта; не создавай новый продукт из шаблона. Не скачивай только папку `app/` или отдельный архив файлов: нужен корень вместе с Git и базой знаний.

Проверь полученный клон:

```powershell
git remote -v
git branch --show-current
git log -1 --oneline
git status --short
```

Адрес `origin` должен быть `https://github.com/TomashPetersen/rodoslovnaya.git`, ветка - `main`, рабочее дерево - чистым. В корне должны быть `AGENTS.md`, `INDEX.md`, `KNOWLEDGE-POLICY.md`, `README.md`, а также `app/`, `knowledge/`, `plans/`, `scripts/`, `research/`, `research-data/`, `retrospectives/` и `ops/`. Скрытые `.github/` и `.gitattributes` также входят в клон.

Каталоги зависимостей, сборки, локальных результатов и сторонние установщики исключены из Git намеренно. Настоящая семейная база, чаты, личные настройки и навыки другого Codex с репозиторием не передаются.

## 4. Открой корень в Codex и прочитай правила

Работай с корневой папкой `rodoslovnaya`, а не только с `app/`. Если можешь управлять локальными проектами приложения, добавь эту папку и выбери ее основной. Если такой возможности нет, покажи Наталье абсолютный путь: она один раз добавляет папку как локальный проект по [инструкции OpenAI](https://learn.chatgpt.com/docs/projects#use-local-projects-for-folders-and-codebases). Продолжай доступные действия установки в этой папке. Клонирование само по себе не гарантирует появления проекта в списке приложения.

Перед работой прочитай локальные файлы в таком порядке:

1. [Инструкции агента](../AGENTS.md).
2. [Карта проекта](../INDEX.md).
3. [Политика знаний](../KNOWLEDGE-POLICY.md).
4. [Текущее состояние](CURRENT-STATE.md).
5. [Маршруты задач](INDEX.md#маршруты-задач).
6. [Инструкция приложения](../app/README.md) и [совместная работа](collaboration.md).

Применяй свои общие инструкции и инструкции репозитория. Отсутствие личной базы владельца и его навыков не блокирует установку. Отвечай по-русски, без длинного тире; сохраняй точные команды, пути и идентификаторы. До отдельной задачи не меняй код, зависимости, требования продукта или семейные данные.

## 5. Установи зависимости и проверь проект

Из корня выполни проверки базы знаний:

```powershell
node scripts/check-knowledge.mjs --self-test
node scripts/check-knowledge.mjs
```

Ожидается успешное завершение самопроверки и отсутствие ошибок ссылок. Предупреждения о локальных материалах исследования разбирай по [правилам проверки БЗ](../scripts/README.md), не скачивай исключенные программы ради их устранения.

Перейди в приложение и установи точные версии из `package-lock.json`:

```powershell
cd app
npm.cmd ci
```

При ошибке останови зависимые шаги и разберись с конкретной причиной. Не заменяй команду на изменение списка зависимостей. Не применяй `npm audit fix`, `--force` или `--legacy-peer-deps` ради прохождения установки.

Из `app/` последовательно выполни:

```powershell
npm.cmd run format:check
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd audit --omit=dev
npm.cmd audit
```

Запиши код завершения каждой команды. Проверки кода и сборка должны завершиться успешно. Полный аудит может вернуть ненулевой код из-за зафиксированных замечаний средств разработки; это не успешный аудит. Сравни результат с [условиями отправки](git-preparation.md) и [журналом передачи](../research-data/github-handoff-2026-11-20.json), отдельно сообщи новые замечания и их тяжесть. Не исправляй зависимости в рамках установки. Успешный аудит рабочих зависимостей проверяется отдельно.

## 6. Выполни браузерные испытания

Перед испытаниями убедись, что сборка завершена и порт `4173` свободен. Проверки сами запускают сервер просмотра. Не завершай чужие процессы ради освобождения порта.

В отдельном терминале испытаний из `app/` задай режим автоматической проверки и выполни настольный проект:

```powershell
$env:CI = '1'
npm.cmd run test:browser -- --project=chromium --timeout=30000
```

Затем перечисли все `tests/*.spec.ts` и последовательно выполни каждый файл отдельным процессом. Для каждого файла команда имеет вид:

```powershell
npm.cmd run test:browser -- tests/FILE.spec.ts --project=mobile-chromium --timeout=30000
```

Заменяй `FILE.spec.ts` реальным именем из каталога `app/tests/`. Выполни все найденные файлы, сохрани результат каждого, проверь отсутствие пропусков файлов. Пустой список и любой ненулевой код означают неуспех всей серии. Не запускай два браузерных процесса одновременно. Оба проекта используют Edge; имитация телефона не заменяет проверку настоящего телефона.

Используй только вымышленные данные и отдельные профили браузера. При отказе памяти, нехватке места или превышении времени сохрани ошибку. Не повышай пороги и не отключай сценарии. После испытаний закрой отдельный терминал, чтобы его значение `CI` не влияло на обычный запуск.

## 7. Запусти приложение и проверь экран

Из `app/` запусти сервер разработки как длительно работающий процесс:

```powershell
npm.cmd run dev
```

Дождись сообщения о готовности. Открой точный локальный адрес из вывода в отдельном профиле браузера. В чистом хранилище должен появиться экран «С кого начнем?». При доступном управлении браузером проверь его сам. Если браузер недоступен агенту, сообщи это и передай Наталье адрес и название ожидаемого экрана; не выдавай HTTP-ответ сервера за визуальную проверку.

Для проверки записи создай вымышленного человека «Тестовый Человек», обнови страницу и проверь сохранение записи. Если используемый профиль уже содержит настоящую семью, не меняй ее: открой другой профиль. Для остановки своего сервера используй `Ctrl+C` или остановку его конкретного процесса.

Адрес разработки доступен на этом компьютере. Он не открывает приложение телефону по локальной сети. GitHub хранит код; семейные сведения остаются в браузере.

## 8. Проверь собранное приложение и работу без сети

После остановки своего сервера разработки проверь собранное приложение из `app/`:

```powershell
npm.cmd run preview -- --port 4173 --strictPort
```

Открой `http://127.0.0.1:4173` в отдельном профиле и дождись сообщения «Доступно без интернета». После первого успешного открытия проверь повторное открытие без сети; при доступной установке веб-приложения проверь и ее. Если инструментов для этого нет, укажи конкретный непроверенный пункт. Адрес просмотра и адрес разработки имеют разные браузерные хранилища: созданный на одном адресе человек не обязан появляться на другом.

Выбери один из двух режимов для дальнейшей работы и оставь запущенным только свой нужный сервер. Для изменения кода нужен `npm.cmd run dev`. Для проверки собранной устанавливаемой версии нужен `npm.cmd run preview -- --port 4173 --strictPort`; после изменения кода сначала повтори сборку.

## 9. Разбери ошибки установки

| Симптом                                                   | Что делать                                                                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Команда не найдена после установки                        | Открой новый терминал, проверь путь и версию; при необходимости перезапусти Codex после сохранения работы.                                        |
| PowerShell запрещает запуск `npm.ps1`                     | Используй `npm.cmd`. Не отключай системную политику исполнения.                                                                                   |
| Git просит вход для клонирования                          | Проверь публичный HTTPS-адрес без имени и токена, прокси и сетевой доступ. Не запрашивай аккаунт владельца.                                       |
| Ошибка сети при `npm.cmd ci`                              | Сохрани сообщение, проверь доступ к реестру пакетов и повтори после устранения сетевой причины. Не отключай проверку сертификатов.                |
| Не найден Edge                                            | Установи Microsoft Edge с официального сайта; загрузка Chromium через Playwright не заменяет нужный браузер.                                      |
| Порт `4173` занят                                         | Найди владельца процесса. Останови только собственный сервер либо сообщи, какая программа мешает испытаниям.                                      |
| Недостаточно места или памяти                             | Освобождение чужих данных не выполнять. Выбери доступный диск для временных файлов, затем повтори пострадавшую проверку и сохрани оба результата. |
| Новый клон не содержит `node_modules` или семейных данных | Это ожидаемо: зависимости устанавливает `npm.cmd ci`, а семью Git не переносит.                                                                   |

## 10. Подготовь передачу результата и дальнейшую работу

Сохрани местный отчет в исключенном из Git каталоге `output/`: дата, ОС, версии инструментов, абсолютный путь клона, адрес `origin`, ветка, идентификатор коммита, команды с кодами завершения, результаты браузерных проверок и оставшиеся ограничения. Не включай в отчет секреты, настоящие семейные сведения или содержимое личных файлов.

Сообщи Наталье:

- где находится корень проекта и добавлен ли он в Codex;
- какой сервер работает, точный адрес и как его остановить;
- что установлено и какие проверки прошли;
- какие действия потребовали ее участия и что осталось непроверенным;
- что можно начинать следующую задачу, если установка и обязательные проверки завершены.

Пока GitHub-аккаунта нет, можно читать проект, запускать и менять его локально. По умолчанию заверши установку без коммитов, отправки и создания PR. Не регистрируй Наталью и не используй учетную запись владельца.

После регистрации Наталья передает владельцу имя аккаунта, принимает приглашение, создает отдельную ветку `codex/natalya/TASK_SLUG` от актуальной `main` и работает по [инструкции совместной работы](collaboration.md). `TASK_SLUG` означает короткое название задачи латиницей с дефисами. Отправка ветки и создание PR, запроса на включение изменений, требуют отдельного поручения Натальи. Проверяет и разрешает объединение владелец проекта. Прямую отправку ее изменений в `main` не выполнять.

Готовность установки не закрывает [приемку настоящих телефонов и семейного испытания](CURRENT-STATE.md#следующий-этап). Изменение опубликованного приложения в эту задачу не входит.

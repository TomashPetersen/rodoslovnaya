# Политика базы знаний проекта

## Назначение и приоритет источников

База знаний хранит решения, основания, маршруты к коду и результаты проверок «Родословной». Семейная база IndexedDB в браузере - отдельное хранилище приложения; настоящие семейные сведения в эту БЗ не входят.

Прямые указания владельца и применимые `AGENTS.md` определяют разрешенные действия. [Единый план продукта](plans/2026-11-15-rodoslovnaya-mvp-pwa.md) определяет согласованный состав и приемку. Код показывает реализованное поведение; датированные журналы показывают, что действительно проверялось. При противоречии плана и кода зафиксировать расхождение, а не молча объявлять одну сторону верной.

Историческое исследование, разборы, память Codex и история чата не заменяют актуальные требования и проверку состояния. Последующий разбор не дает разрешения на внешние действия.

## Как обновлять знания

1. Найти владельца сведений по таблице. Проверить текущие файлы, применимый план и исходное состояние Git.
2. Отделить наблюдавшийся факт от документации поставщика, сообщения пользователя, вывода, гипотезы и неизвестного. Для решения владельца указать его содержание и источник; не объявлять исследовательскую рекомендацию утвержденным решением.
3. Исправить владельца. Для изменчивых наблюдений создать датированную запись с командой или способом проверки, средой, результатом, ограничениями и источниками. Не менять старый неуспешный результат на успешный без новой записи.
4. Добавить обычные относительные ссылки в нужную карту и обратный путь. Для значимых связанных документов дополнить их вики-ссылками. Обновить текущее состояние, только если изменился смысловой статус.
5. Сохранить исторические доказательства. При переносе сначала исправить входящие ссылки; удаление или массовое перемещение требует точных целей и отката. Не создавать неподтвержденные заглушки ради графа ссылок.
6. Выполнить [проверку БЗ](scripts/README.md), независимый разбор существенных изменений и отдельную языковую вычитку. Записать результат в применимом плане и разборе.

Если код не менялся, совпавшие контрольные суммы подтверждают только совпадение перечисленных файлов. Перед отправкой общего коммита нужны текущие проверки всего стека; прежние результаты остаются историческими.

## Ссылки и маршруты

Основная навигация - обычные Markdown-ссылки относительно файла, например `[Карта базы](knowledge/INDEX.md)`. Они работают в GitHub. Регистр имени должен точно совпадать с файлом; якорь должен соответствовать существующему заголовку. Для текста ссылки на внешний источник использовать его название и прямой URL.

Вики-ссылки нужны для Obsidian, программы связанных заметок, и поиска. Формат: `[[knowledge/INDEX|Карта базы]]`, путь от корня проекта без `.md`. Для раздела допустим `[[knowledge/architecture#хранение-и-версии|Хранение]]`. Не использовать короткие неоднозначные имена вроде `[[INDEX]]` для вложенных карт; `[[INDEX|Карта проекта]]` означает только корневой файл. Вики-ссылки вести только на Markdown-документы БЗ, для кода, JSON и изображений использовать обычные ссылки.

Ключевой маршрут должен существовать и в обычных ссылках. Все документы БЗ должны быть достижимы из [корневой карты](INDEX.md). Примеры синтаксиса в обратных кавычках не являются действующими ссылками.

## Актуальность, данные и внешние действия

Цены, доступность, версии сервисов, правовые требования и результаты аудита зависимостей использовать с датой проверки. Перед новым зависимым решением перепроверять первоисточник. Отсутствие сведений не означает отсутствие функции. Техническая работоспособность не подтверждает спрос или готовность платить.

Публиковать только исходники, документы и проверенные вымышленные данные. Настоящие фотографии семьи, документы, копии, контактные сведения, секреты и содержимое браузерного хранилища не сохранять в Git. Участников испытаний и внутренние документы не отправлять наружу без явного разрешения и необходимости.

Сторонние программы в `research-data/apps/` и `research-data/downloads/` исключены из Git и не нужны для чистого клона. Если будущий отчет ссылается на такой локальный артефакт, обычная ссылка должна иметь заголовок `"local-only"` и пояснение, что файл доступен только на машине исследования. Вики-ссылки на такие артефакты запрещены. Не скачивать и не запускать их автоматически для устранения предупреждения проверки.

Личная общая база владельца доступна из проекта только для чтения на его рабочем месте. Другим разработчикам для работы достаточно файлов репозитория; переносить личную базу не нужно. Обновление проектной БЗ не разрешает обновлять общую базу, память Codex, выполнять `commit`, `push` или публиковать приложение.

# Передача проекта для совместной работы

Дата: 20 ноября 2026 года. Задача продолжает [план подготовки](../plans/2026-11-17-knowledge-navigation.md#передача-в-публичный-репозиторий-20-ноября).

## Что меняется

По прямой команде владельца создан новый публичный [репозиторий GitHub](https://github.com/TomashPetersen/rodoslovnaya). Первый общий коммит включает существующее приложение, исследование, БЗ, материалы размещения и инструкции совместной разработки. Семейная база браузера и ее копии не передаются.

В инструкции агента устранена обязательная зависимость от личной базы владельца. Корневой README описывает установку зависимостей и запуск на другом компьютере. [Инструкция Натальи](../knowledge/collaboration.md) различает клонирование, открытие корневой папки в Codex, ветку задачи и PR, запрос на включение изменений. Для работы до приглашения описана собственная копия репозитория GitHub (fork).

Настройка `.github/workflows/checks.yml` запускает проверки на Windows с Microsoft Edge. Режимы компьютера и имитации телефона выполняются последовательно в разных процессах, с прежними условиями испытаний. Полный аудит средств разработки выводится отдельным отчетом; его неуспех не объявляется нулем замечаний. Обязательная проверка разрешает только два уже известных бюллетеня умеренной тяжести, отклоняет новые/поврежденные сведения, высокие и критические уязвимости. Рабочие зависимости проверяются обязательным шагом без такого исключения. Файл `.github/CODEOWNERS` назначает владельца для проверки, но его наличие само по себе не включает обязательное одобрение: нужны правила GitHub.

## Доказательства и ограничения

Новый [журнал передачи](../research-data/github-handoff-2026-11-20.json) содержит свежие команды, коды завершения, оценку замечаний, проверку состава и результаты БЗ. Исторические журналы 17 ноября сохранены. Более поздний успешный прогон размещения не стирает предыдущие превышения времени поиска.

Первый общий браузерный прогон этой задачи получил отказ выделения памяти в тестовом процессе. Узкий повтор остановился на загрузке ресурсов с `ERR_INSUFFICIENT_RESOURCES`, сообщением о недостатке ресурсов. Эти исходные результаты сохранены; последующие проверки выполняются отдельно по режимам. Причинная связь с параллельными испытаниями других проектов не установлена. Код и пороги приложения для получения успешного результата не менялись.

Окончательное покрытие получено полным настольным прогоном и мобильной серией по всем шести файлам в новых процессах. Сопоставление идентификаторов подтвердило полный исходный состав мобильных сценариев без дополнительных пропусков. Это успешная проверка того же поведения при изоляции исполнителя, а не доказательство устранения первопричины предыдущих отказов памяти.

Независимый разбор исправил неоднозначность `origin` после приглашения участника, работавшего через fork: приглашение не меняет адреса существующего клона. Проверка полного аудита получила положительные и отрицательные примеры, включая поврежденный бюллетень без URL. Окончательные документы прошли отдельную языковую вычитку по точному списку файлов с ручным разбором латиницы.

Локальные проверки не подтверждают еще не завершенный запуск GitHub Actions или работу на компьютере Натальи. Установка зависимостей из чистого клона выполняется на стороне получателя и в автоматических проверках. Личные навыки, настройки Codex и история чатов не входят в Git. Настоящие телефоны и самостоятельное семейное испытание остаются открытой приемкой продукта.

У Натальи еще нет аккаунта GitHub, приглашение не отправлено. Для клонирования публичного проекта и локальной работы он не нужен; для отправки веток и PR потребуется регистрация. Настройка правил основной ветки и состояние первоначальной отправки проверяются отдельно по GitHub; после отправки история не переписывается принудительно. Размещенное приложение этой задачей не обновляется.
